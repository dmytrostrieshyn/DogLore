# Журнал ризиків (Risk Log)

*Цей документ використовується під час виконання проекту для відстеження поточних проблем, технічних блокерів та статусу їх вирішення (Актуалізовано: 15 травня).*

| ID | Опис ризику / Проблеми | Статус | Відповідальний | Вжиті заходи (Мітигація) |
| :--- | :--- | :--- | :--- | :--- |
| **RL-01** | **Недооцінка складності (Зрив строків):** Початковий план розробки за 1 день виявився нереалістичним через складність налаштування Firebase та логіки React-роутингу. | Вирішено | Уся команда | Спринт офіційно розширено до 5 днів (11-15 травня). Завдання жорстко розпаралелено (створено окремі гілки `feat/backend-base` та `front`). Оновлено Діаграму Ганта. |
| **RL-02** | **Архітектурна перевантаженість БД:** Спроба зберігати масиви даних (історія ваги, тренування, галерея) у головному документі собаки призводила до лімітів Firebase. | Вирішено | Backend Team | Впроваджено модульний `dbService.js`. Архітектуру змінено: дані винесено у підколекції (`health_logs`, `training_logs`, `chronology`). |
| **RL-03** | **Проблема стану авторизації:** Після входу сторінка профілю видавала помилку "Собаку не знайдено" через втрату `dogId` при редиректі. | Вирішено | Front Team | Впроваджено глобальний стан (`AuthContext`) для збереження сесії користувача. | **RL-04** | **Складність стилізації динамічних SVG:** Конфлікти класів Tailwind та необхідність дублювати файли іконок для різних станів меню (Active/Inactive). | Вирішено | Design/Front | Створено гілку `design-assets`. | **RL-05** | **Краш UI через порожні поля:** Сторінка профілю ламалася (`Objects are not valid as a React child`), якщо користувач при реєстрації не вказував дату щеплення або вагу. | Вирішено | Front Team | Додано логіку безпечного рендеру з перевірками (Graceful Handling) та заглушками ("Не вказано"). Формат дат переведено у `.toDate().toLocaleDateString()`. |
