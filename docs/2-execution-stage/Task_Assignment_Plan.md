# План розподілу завдань (Task Assignment Plan)

*Актуалізовано 15 травня. Документ відображає реальний розподіл обов'язків та зон відповідальності під час 5-денного спринту розробки проекту DogLore.*

## 1. Технологічний стек проекту
* **Frontend:** React.js, Tailwind CSS, React Router.
* **State Management:** React Context API (глобальний стан авторизації).
* **Backend / База даних:** Firebase Firestore (з використанням підколекцій).
* **Автентифікація:** Firebase Auth.
* **Хостинг:** Firebase Hosting / Vercel.

## 2. Детальний розподіл завдань за ролями

### Стрієшин Дмитро (Team Lead / Lead Developer)
**Зона відповідальності:** Архітектура фронтенду, глобальний стан, координація розробки.
* **Завдання:**
  1. Ініціалізація проекту, налаштування Tailwind CSS та роутингу.
  2. Верстка UI-компонентів ("Енциклопедія", "Профіль", навігація) за макетами.
  3. Впровадження глобального стану (`AuthContext`) для керування сесіями та передачі `dogId`.
  4. Координація злиття гілок (merge) у GitHub, вирішення конфліктів коду.
  5. Фінальний багфікс UI (безпечний рендер порожніх полів) та деплой проекту.

### Бойко Богдан (Backend / Web Developer)
**Зона відповідальності:** Архітектура бази даних, API-шар та бізнес-логіка.
* **Завдання:**
  1. Налаштування Firebase Auth та правил безпеки Firestore.
  2. Проектування архітектури Firestore (розбиття даних на підколекції: `health_logs`, `training_logs`, `chronology`).
  3. Розробка модульного API-шару (`dbService.js`) для універсальних CRUD-операцій.
  4. Написання логіки прив'язки автентифікованого користувача до профілю собаки.

### Ледовських Ольга (UI/UX Designer)
**Зона відповідальності:** Дизайн-система, графіка та візуальний контроль.
* **Завдання:**
  1. Прототипування інтерфейсів у Figma (UI/UX).
  2. Формування Styleguide: палітра кольорів (Deep Green, Peach) та типографіка (Urbanist, Montserrat).
  3. Підготовка та експорт фірмових SVG-іконок для динамічного використання (налаштування під Tailwind `invert`).
  4. Візуальний контроль (UI Review) зверстаних компонентів на відповідність макетам.

### Білоус Віктор (QA Engineer)
**Зона відповідальності:** Тестування, стабільність та фіксація ризиків.
* **Завдання:**
  1. Проведення 3-денного циклу тестування паралельно з розробкою.
  2. Тестування логіки авторизації (втрата сесії, редиректи).
  3. Перевірка стабільності UI при відсутності даних у базі (перевірка Graceful Handling).
  4. Ведення Журналу ризиків (`Risk_Log.md`) та оформлення баг-репортів.

### Порохнавець Денис (Content Manager / Data Analyst)
**Зона відповідальності:** База знань, контент та оптимізація медіа.
* **Завдання:**
  1. Збір та структурування детальних даних про породи собак для Енциклопедії.
  2. Наповнення бази даних Firestore початковим контентом (Breeds collection).
  3. Створення демо-даних для тестування профілів (історія ваги, тестові фото).

## 3. План синхронізації команди (Пофазово)
Замість початкового одноденного плану, команда перейшла на фазову синхронізацію:
* **Фаза 1 (11.05 - 12.05):** Синхронізація щодо UI-компонентів та базової інфраструктури (Front + Design).
* **Фаза 2 (12.05 - 13.05):** Інтеграція модульного бекенду та проектування підколекцій (Lead + Backend).
* **Фаза 3 (14.05):** Наповнення контентом та злиття логіки (Auth Context) у спільну гілку (Уся команда).
* **Фаза 4 (15.05):** Фінальне QA-тестування, фікс критичних багів UI та підготовка до релізу.
