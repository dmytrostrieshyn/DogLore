# Ієрархічна структура робіт (Work Breakdown Structure - WBS)

*Актуалізовано 15 травня. Структура відображає фактичний обсяг робіт (Scope) реалізованого MVP-проекту DogLore.*

## 1. Ініціалізація та Проектування (Phase 1)
* **1.1. Інфраструктура**
  * 1.1.1. Створення GitHub-репозиторію та налаштування гілок.
  * 1.1.2. Ініціалізація React-проекту (Vite).
  * 1.1.3. Налаштування Tailwind CSS та конфігурації стилів.
* **1.2. Проектна документація**
  * 1.2.1. Розробка Project Charter та Scope Statement.
  * 1.2.2. Формування RACI матриці та Risk Management Plan.
* **1.3. UI/UX Дизайн**
  * 1.3.1. Створення макетів сторінок у Figma.
  * 1.3.2. Підготовка фірмової графіки та SVG-іконок.

## 2. Frontend Розробка (Phase 2)
* **2.1. Базова верстка**
  * 2.1.1. Створення Layout (Navbar, Sidebar).
  * 2.1.2. Верстка сторінки "Енциклопедія" (DogCard).
  * 2.1.3. Верстка сторінки "Профіль собаки" (графіки, галерея).
  * 2.1.4. Верстка сторінки "Трекінг" (прогрес-бари команд).
* **2.2. Маршрутизація (Routing)**
  * 2.2.1. Налаштування React Router для базових сторінок.
  * 2.2.2. Створення динамічних маршрутів (напр., `/encyclopedia/:breedId`).

## 3. Backend та База Даних (Phase 3)
* **3.1. Автентифікація (Firebase Auth)**
  * 3.1.1. Налаштування реєстрації та входу користувачів.
* **3.2. Архітектура Firestore**
  * 3.2.1. Проектування статичної колекції `breeds`.
  * 3.2.2. Проектування колекції `dogs` та підколекцій (`health_logs`, `training_logs`, `chronology`).
  * 3.2.3. Налаштування правил безпеки (Security Rules).
* **3.3. Модульний API-шар**
  * 3.3.1. Створення базового `dbService.js` для CRUD операцій.
  * 3.3.2. Реалізація методів для `dogsApi.js` та `trainingApi.js`.

## 4. Інтеграція та Логіка (Phase 4)
* **4.1. Глобальний стан (State Management)**
  * 4.1.1. Створення `AuthContext` для зберігання сесії користувача.
  * 4.1.2. Реалізація логіки зв'язування `User UID` з `Dog ID`.
* **4.2. Обробка даних UI**
  * 4.2.1. Конвертація дат (Firebase Timestamp у формат локалі).
  * 4.2.2. Graceful Handling: безпечний рендер порожніх полів при реєстрації.

## 5. Тестування, Контент та Реліз (Phase 5)
* **5.1. Наповнення контентом**
  * 5.1.1. Створення JSON-структур для 20+ порід собак.
  * 5.1.2. Завантаження даних у колекцію `breeds`.
* **5.2. QA та Багфікс**
  * 5.2.1. Крос-браузерне тестування UI-компонентів.
  * 5.2.2. Тестування логіки реєстрації та втрати сесії.
  * 5.2.3. Фікс конфліктів класів Tailwind.
* **5.3. Деплой**
  * 5.3.1. Збірка (Build) проекту.
  * 5.3.2. Деплой на хостинг та перевірка live-версії.
